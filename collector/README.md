# Сборщик афиши «Клубок»

Раз в сутки собирает детские события Белграда из открытых источников и пишет `../data/events.json`.
Сайт (`Клубок — события для детей в Белграде.dc.html`) читает этот файл при загрузке; если файла нет
или он пустой — показывает встроенную демо-афишу.

## Локальный запуск

```bash
cd collector
npm install
npm run collect
```

Внешних зависимостей нет — все источники читаются обычным `fetch`.

## Что откуда берётся

| Источник | Как | Что может сломаться |
| --- | --- | --- |
| `instagram.com/p/…` | публичная страница `/embed/captioned/`: подпись + превью. Если задан `IG_OEMBED_TOKEN` — сначала Graph oEmbed | инстаграм меняет разметку эмбеда или закрывает пост; тогда источник помечается `error` в отчёте |
| `reg.prodlenka.me/schedule` (Продлёнка + Kinder Garden) | публичный REST base44 без авторизации: справочники `Location` и `Class` (название с возрастом, описание, цена, длительность, фото) джойним с `Schedule` (дата, время, занятость мест) и `getBookedCounts`. Каждое проведение из расписания на ближайшие `horizonDays` (28) дней → отдельное событие; площадка выбирается по `locationSlug` в `sources.json`. Сейчас расписание заполнено только для Kinder Garden | смена `appId` в URL API, переименование сущностей/полей base44 или slug'ов площадок |
| `enterspace.rs/classes` | статичный Tilda-сайт: со страницы `/classes` собираем ссылки на занятия, с каждой страницы регулярками вытаскиваем день/время («Когда»), возраст и время из `<meta name="description">`, цену и первое реальное фото | сайт банит IP при частых запросах подряд (между страницами пауза 800 мс); смена вёрстки Tilda-блоков сломает метки-якоря («Контакты», «Когда», «Разовое занятие —») |
| `math-line.ru/beograde/reg` (Sreda Kids + Mathline) | статичный Tilda-сайт: расписание каждой локации — отдельная форма записи (rec-блок с чекбоксами по дням недели), формы идут на странице подряд и не подписаны; по договорённости первая (`formIndex: 0`) — Стари Град, Косовска 32, вторая (`formIndex: 1`) — Дорчол, Тадеуша Кошћушка 63. Парсим строки вида `ЧЧ:MM-ЧЧ:MM Название (возраст)` только под заголовками пн/вт/ср/пт/сб (чт и вс пропускаем по договорённости); описания занятий подставляются по названию из таблицы `DIRECTION_INFO` (тексты со страниц «Направлений» сайта) | смена порядка форм (локации перепутаются) или их вёрстки, переименование дней недели/заголовков-стопов («Продленка в MathLine», «Продлёнка Weekend») |
| `t.me/<канал>/<id поста>` (Индиго) | публичный embed-виджет поста (`?embed=1&mode=tme`) отдаёт текст без логина, даже если сама группа закрыта; текст — расписание по дням недели, строки вида `ЧЧ:MM Название возраст` | студия редактирует один и тот же пост при смене сезона (сейчас «летнее расписание») — если сменят формат строк или уберут заголовки дней недели, парсер перестанет находить события |
| `beopinokio.rs/reg` + `/group` (ЛаборатоРиЯ) | статичный Tilda-сайт. Расписание — в форме записи (`/reg`): чекбокс-группы по дням недели (`t-input-title` = «Понедельник» … «Воскресенье»), внутри `<input type="checkbox" value="ЧЧ.ММ Название возраст">`. Берём value чекбоксов под заголовками-днями, одно занятие в несколько дней склеиваем по «заголовок+время». Индивидуальные занятия (`/индивидуальн/i`) не берём по договорённости. Описание (первый абзац) и фото каждого занятия подтягиваем со страницы `/group` — карточки Tilda-блоков T422; расписание с карточкой сопоставляем по общим корням слов в названиях | смена вёрстки формы Tilda (`t-input-group` / `li_title__…`) или карточек T422 (`t422__title` / `t422__descr` / `data-original`); переименование дней недели; расхождение названий в расписании и на `/group` |
| `besmartserbia.com/lessons` (BeSmart) | Tilda-каталог «Список занятий» (блок t-catalog) подгружает карточки скриптом, поэтому берём JSON store-API Тильды: `GET store.tildaapi.com/api/getproductslist/?storepartuid=…&recid=…` (значения — из `options` в inline-скрипте `t_catalog_init`). На `…tildaapi.com` API отвечает `{"redirectto":"one"}` — повторяем запрос на `…tildaapi.one`. Из `descr` каждого продукта регулярками достаём преамбулу «Возраст: …» и «Расписание: <день(и)>, ЧЧ:ММ [- ЧЧ:ММ]», тело (после `<br><br>`) — в описание, цену — из поля `price`. Занятия еженедельные → событие с массивом `wd`. Черновики-дубли (`Copy: …`) и продлёнку пропускаем; строки без дня недели («набор с января», «каждый день в будни») отбрасываются | смена `storepart`/`recid` каталога, другой ответ вместо `redirectto`, переименование меток преамбулы («Возраст:», «Расписание:») или формата дней/времени в ней |
| `bilet.bgf.rs/repertoar.php` (Београдска филхармонија) | Весь сезонный репертуар отдаётся одним `POST qrydata.php` (тот же запрос, что страница шлёт сама в режиме «цела сезона») — без логина и кук. Вперемешку взрослые абонементные концерты и детские серии («Концерти за бебе/предшколце/школарце»); берём только строки с непустым `url` на карточку `www.bgf.rs/repertoar_cp/…`, у которой путь содержит `bebe`/`predskol`/`skolarc` — это и есть признак детского сеанса с отдельной продажей билетов. Со страницы карточки регулярками достаём заголовок, описание и цену (в JSON репертуара их нет); ссылка на билет строится из `prostorterminid` (`scena.php?prostorterminid=…`) | смена структуры ответа `qrydata.php` или параметров запроса (`tip_prikaza` и др.), переименование slug'ов детских серий, смена вёрстки блока `concert-content` на карточке |
| `panteatar.rs/repertoar` (Пан театар) | Серверная вёрстка, без API. Репертуар — по странице на месяц: `GET /repertoar?scene=decja-scena&month=YYYY-MM` (берём текущий и два следующих; «Večernja scena» — взрослая, не берём). Каждый показ — `<article id="izvodjenje-N">`: дата/время из `<time datetime>`, афиша, название (ALLCAPS → «Sentence case»), «4+ · 45 min» (возраст/длительность могут отсутствовать). Со страницы `/predstave/<slug>` — синопсис из блока «O predstavi» (пропуская «Uzrast:» и список титров) и возраст из факта «Uzrast», если его нет в списке. Только разовые датированные показы, цена на сайте не публикуется («уточняется»); язык — сербский латиница | смена вёрстки `performance-row` / `production-facts`, переименование `scene`-параметра или slug'а детской сцены, смена формата `datetime` |

Картинки скачиваются в `data/images/` — CDN-ссылки инстаграма подписаны и умирают через несколько дней.

## Схема события

```json
{
  "id": "9f1c2b…",
  "title": "Лесной клуб на Ада Циганлии",
  "short": "Строим шалаши и завариваем чай",
  "desc": "полный текст источника",
  "date": "2026-08-22",        // разовое событие
  "wd": [0,2,4],               // либо еженедельное: 0 = понедельник
  "time": "11:00",
  "dur": "3 часа",
  "place": "Ада Циганлия",
  "address": "Вход у велодорожки",
  "age": [4, 10],
  "ageLabel": "4–10 лет",
  "price": "бесплатно",
  "image": "data/images/ig-DZuvdMejdSV.jpg",
  "source": { "name": "Instagram", "kind": "Инстаграм-пост", "url": "https://…", "cta": "Открыть пост в Instagram" }
}
```

## Добавить источник

1. Допишите объект в `collector/sources.json` (`type`: `instagram`, `prodlenka`, `enterspace`, `mathline`, `telegram`, `beopinokio`, `besmart`, `pinokio`, `panteatar` или `bgf`).
2. Для источника нового типа — файл в `collector/sources/`, экспортирующий `collect…(source, now)` и возвращающий события через `normalize()`, и строка в `RUNNERS` в `index.mjs`.

Разбор текста (дата, время, возраст, цена) живёт в `collector/lib/text.mjs` — правила русскоязычные, дополняйте по мере появления новых формулировок.

## Автосбор

`.github/workflows/collect.yml` — cron каждый день в 04:10 UTC + запуск руками. Коммитит `data/`, если файл изменился.
Модерации нет: всё собранное публикуется сразу. Отчёт по каждому источнику — в `data/events.json` → `report`,
и в логах Actions (`console.table`).

### Отчёт в Telegram

Если в секретах репозитория заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, после каждого прогона
`collector/lib/notify.mjs` шлёт в этот чат текстовое сообщение: список площадок с числом собранных
событий, общий итог и ошибки. Только уведомление — ни кнопок, ни команд. Без секретов шаг молча
пропускается (локальный запуск ничего не отправляет). Бот и chat_id — те же, что у функции
`supabase/functions/suggest-event` (см. её README, шаги 1–2).
